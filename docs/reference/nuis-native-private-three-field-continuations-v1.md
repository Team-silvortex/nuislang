# Native Private Three Field Continuations V1

This is the frozen complete 441-test receipt. The subsequent
[retained-owner follow-up](nuis-native-retained-owner-three-field-continuations-v1.md)
records initial child-only selections under an existing Target separately.

The persistent application-session CPU path carries one outward numeric owner
beside two separately certified private numeric children through bounded
terminal selections and nested sequential continuations. It follows the
complete 430-test predecessor,
[float/i32](nuis-native-private-float-i32-continuations-v1.md).

## Single Outward Target

A separate lexical certificate admits exactly two mutable children already
defined in the current prefix, absent from the entering scope and not sealed.
The complete initial selection must write the authorized owner and both private
children across its arms. All three types must be exact unqualified i32, i64,
f32 or f64. The source helper still returns **bool**; only its one authorized
outward owner reaches the enclosing return prefix.

The original pair classifier remains unchanged: its two-write limit is not
raised. The new classifier collects known-binding write evidence under the
existing 64-node/depth bound, then validates each child's prefix definition,
type, entering-scope exclusion and seal before granting its separate token.
It does not invent another outward target or use a fixed backend/type tuple.

Readonly entering values, private scope, current/retained versions, both write
orders and original bounds remain mandatory. Unrelated entering writes, sealed
or qualified/resource/unsigned fields, bool combinations, more children,
hidden ordinary leaves, child leaks and partial exits reject atomically.
Historical numeric sibling negative tests now use sealed siblings: an otherwise
eligible second private numeric child is no longer rejected merely by count.
Their readonly, qualifier, hidden-work, leak and input/name atomicity checks stay.

## Field Driven Transport

The shared record assembler takes independent labels, bindings and field types,
rather than a hardcoded two-field or backend-specific tuple. The original pair
adapter preserves its owner/child labels and private type/carrier naming prefixes.

The new closed compiler-private record uses stable owner/child_0/child_1 labels.
The native fixture has:

```text
owner: i64 / child_0: i32 / child_1: f32 or f64
```

Each field has its own original-width neutral and projection. The i32 neutral
uses the existing checked cast of literal i64 zero; IEEE fields retain their
own zero types. Both selected arms and inactive neutrals use the same layout.
No field borrows another's payload bits, selects the bool/i32 codec, numerically
converts a live value, exports a private child or introduces owned allocation/drop.

The representation test checks all 64 exact ordered numeric type triples.
This is structural type-driven coverage, not 64 separately executed application/
backend recipes. Fresh names, exact types, three distinct bindings and 31
captures plus a gate are mandatory. All record installation still uses the
existing aggregate YIR call/return contract.

The new sequence proof reuses original-forest preflight and lexical isolation.
It visits each original statement once; no continuation is copied into both
arms. Each nested selection returns all three versions, including explicit
retention, before a shared suffix reads them. Only certified private names may
advance beside the delegated owner. Existing flat-recipe copying rejects
PrivateFields just as it rejects nested selections and PrivatePair.

Four unit families cover both IEEE widths, current values, source orders,
retention, readonly/undefined/sealed/qualified children, extra writes, hidden
work and leaks, independent neutrals and projections. Exact eight-node/eight-
expression/zero-logical-edge proof, adjacent rejection, full 64/65-node forests,
16/17 statements, 31/32 captures and depth 7/8 retain original budgets.

AOT checks exact layouts, i64 owner helper results, guard-first transitive
Effect paths and default/empty-print/removed-Effect vetoes. Live YIR floating/
integer casts and arbitrary i64-owner/proof narrowing reject. Bounded literal
zero/negative-one and width-safe i32 complement, existing canonical bool/i32
restoration and dead auxiliary LLVM bookkeeping remain separate. Synthetic
live floating consumers and f64-to-f32 narrowing reject. The whole LLVM unit
is not claimed cast/codec-free; these structural checks grant no new permission.

## Source And Probes

[The Nuis source](../../tools/nuisc/tests/native_application_bridge/return_private_fields.ns)
accepts three independent seeds and retains them in a seventeen-word state.
Current i32 and IEEE signs jointly control the i64 owner complement. Each child
updates independently: typed i32 negative-one-minus and original-width floating
negation. Both source orders, nested current zero/negative-one stages, shared
suffix reads, seals, unused work and caller continuation remain real computation.

[The independent oracle](../../tools/nuisc/tests/native_application_bridge/return_private_fields_oracle.rs)
crosses three i64 owners, four i32 children, twelve raw IEEE words and both gates:
576 cases per width/inventory. Owners include full-width extrema and a value
outside i32 range. Independent child extrema, zero/negative-one branches, signed
zeros, subnormals, finite values, infinities and quiet/signaling NaN payloads
remain original-width. Replay uses independent integer complements and raw IEEE
sign XOR, never the compiler carrier.

Reference healthy execution covers the full raw matrix. Public f32 state text
follows the existing promoted display, separately from shortest input text;
original raw state words and a smallest-subnormal word-one audit stay unchanged.
Selected reference failure/cleanup inputs remain finite.

Native-only entry probes read actual owner, sign-extended i32 child and raw IEEE
child bits at after-work, then actual final owner at answer-work. They neither
replace source computations nor substitute oracle state into later callbacks.
Both normal/reversed function inventories retain real calls, joins, selected
argument traps, actual accepted-state forwarding and width-driven canaries.

Native late failures carry owner -70002, private integer -70002 and raw float
word 96. Two legal integer fields match a diagnostic sentinel. Full source-event
prefixes distinguish these values from markers and retain real SIGILL/SIGTRAP
without post-failure status/canary publication. Reference cleanup is not native
process recovery, exception rollback or post-crash memory certification.

CLI uses six independent finite triples crossed with both gates: 24 healthy
cases per image. It checks signed zeros, integer extrema, current nested work,
last accepted publication and healthy reentry. Finite CLI inputs and raw IEEE
native seeds are distinct receipts; no NaN payload text roundtrip is claimed.

## Remaining Boundary

The next separate proof at this checkpoint was an initial selection that changes both private
children while retaining the already authorized outward owner without an owner
write in either arm. Prove retained-owner authority rather than infer it from a
field list or loosen entering-scope checks. Current three-field admission still
requires initial owner-write evidence at this frozen checkpoint; the later
[retained-owner receipt](nuis-native-retained-owner-three-field-continuations-v1.md)
records the separate extension without rewriting this 441-test acceptance.

Support for three private children, bool/resource combinations and generalized
private arity remains separate. Preserve original scope/seals, readonly entering values,
forest/capture/depth/statement bounds, actual field/final-owner observations,
marker-safe failures and fresh/cache/two source-free publication identity.

This is a macOS CPU receipt, not new GPU/Linux/Windows execution, measured
performance, formal memory safety, completed self-hosting, full-workspace or
strict-Clippy acceptance. Public ABI stabilization and broader application closure
remain open.
