# Native Private I32 I32 Continuations V1

This complete 400-test checkpoint remains historical. The separate
[i32/float follow-up](nuis-native-private-i32-float-continuations-v1.md)
extends the next orientation without reinterpreting this receipt's scope.

The persistent application-session CPU path carries one exact i32 outward owner
beside an independently initialized private i32 child through bounded terminal
mixed selections and sequential continuations. This completes the four
i32/i64 integer orientations on this bounded route, following the
[i64/i32 checkpoint](nuis-native-private-i64-i32-continuations-v1.md).
It is not a public tuple ABI or general function-return/resource pipeline.

## Single Outward Target

A separate exact unqualified i32/i32 predicate adds only this same-width pair.
Generic owned-record installation remains separate from admission. The source
helper still returns **bool**; only the authorized i32 owner reaches its
enclosing return prefix.

One delegated/prefix-owned outward target, readonly entering values, current/
retained versions, both source write orders, private lexical scope and seals
remain mandatory. Third/unrelated entering writes, qualified/resource fields,
hidden ordinary logical work, child leaks and partial exits reject atomically.
Other i32 orientations involving f32/f64, including either owner/child order,
remain separate proofs rather than a general numeric cross-product.

The old i32-ancestor and forward-integer rejection cases now use sealed i32
children that cannot be rewritten. Unsupported-pair tests retain String,
i32/float and float/i32 rejection. The new four proof families retain whole
input/name atomicity and reference/optional/generic vetoes. No safety assertion
is simply discarded because a formerly unsupported pair is now admitted.

## Exact Private Transport

The closed compiler-private record has two independently typed fields:

```text
owner: i32 / child: i32
```

Both neutrals use the existing checked i32 cast of literal i64 zero.
Both projections read the same selected record but retain distinct field names
and original local/child values. Even though both types are i32, they must not
be collapsed into one value. The same source binding cannot be authorized as
both owner and child; that preparation explicitly rejects.

Installation reuses the existing generic record and early owned-field route,
before the legacy scalar i32-child codec. The new pair does not use bool/i32
packing, borrow bits between fields, replay source work, add owned allocation/
drop, export a private child or grant common effect/backend permission.

The original whole-forest limits remain 64 nodes, 256 expressions, 32 logical
edges, 16 statements per body/suffix, depth eight and 31 captures plus a gate.
The exact seven-node/seven-expression/zero-logical-edge boundary and adjacent
rejections, 16/17 statements, 31/32 captures and depth 7/8 remain tested.

The AOT fixture's narrowing checker accepts bounded literal zero/negative-one
construction, width-safe complement of an already typed i32, and the existing
exact canonical bool/i32 restoration shape with a proved producer. Constant/
producer proof has an eight-level bound. The actual i64 proof parameter is
explicitly rejected as an arbitrary narrowing source. These are test-only
structural checks, not new compiler cast permissions or formal verification.
The surrounding bool/i32 routes remain valid; the whole LLVM unit need not be
codec-free or cast-free merely because the new private pair is independent.

## Source And Probes

[The Nuis source](../../tools/nuisc/tests/native_application_bridge/return_i32_i32_private_pair.ns)
takes independently typed i32 seeds, retained separately in a fourteen-word
state. Current child signs drive owner complement work. Negative-one minus the
value avoids intermediate negation of the signed minimum at either field.
Both calculations establish typed negative-one constants; child sign/zero/
negative-one comparisons use typed literal casts.

Both write orders, nested private zero/negative-one versions, shared continuation,
seals, unused work and caller continuation remain real source computations.
Pair snapshots may differ from the final owner, so a final bool alone cannot
prove correct field identity or current-value transport.

[The independent oracle](../../tools/nuisc/tests/native_application_bridge/return_i32_i32_oracle.rs)
crosses eleven independent i32 seeds per field and both gates: 484 cases per
function inventory. Full signed extrema, zeros/negative-one, source markers and
diagnostic sentinels occur as legal data. Imperative replay uses native-width
complements, never the compiler carrier or bool/i32 codec.

Crossed MIN/MAX and MAX/MIN cases require distinct, opposite extreme field
values. The first also distinguishes the pair snapshot from the final owner.
The reference prefix audit proves these expectations independently, and the
native Cartesian matrix includes both source orders and both function inventories.

Native-only entry probes observe each actual i32 argument separately through
sign extension at after-work and the actual final i32 owner at answer-work.
They replace neither source computations nor accepted state with oracle values.
Both inventories retain real calls, joins, source-order traps, actual accepted
state forwarding and width-driven canaries.

The shared full-trace comparison distinguishes a diagnostic sentinel from a
matching field word. Event-position prefixes, real SIGILL/SIGTRAP and absence of
actual post-failure status/canary publication remain mandatory. Late faults
carry legal owner -70002 beside child 96 before the failure boundary. Reference
fault cleanup does not make native process traps recoverable.

CLI acceptance uses six independent seed pairs crossed with both gates: 24
healthy cases per image. It retains both nested private zero/negative-one paths,
marker-valued fields and the two crossed-extrema cases without a huge CLI corpus.

## Remaining Boundary

The next separate proof is one exact i32 outward owner beside an exact f32 or
f64 private child. Preserve independent original-width integer and IEEE fields,
not numeric conversion or borrowed payload bits. Retain original authority/
budgets, current/retained reads, both inventories, actual raw IEEE and integer
extrema, marker-safe source-order traps, actual-state forwarding/canaries and
fresh/cache/two source-free identity/publication. The reverse float/i32
orientation remains a subsequent independent boundary.

This is a macOS CPU receipt, not new GPU/Linux/Windows execution, measured
performance, formal memory safety, self-hosting, full-workspace or strict-Clippy
acceptance. Broader application-session closure and public ABI stabilization
remain open.
