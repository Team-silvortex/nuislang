## Bounded Write Evidence

Terminal exports remain the preferred target-discovery path. Only when both
terminal trees have no exports does a separate read-only scan look for earlier
source writes. Its eligible names are exact owned bools already defined and
unsealed in the enclosing private prefix, plus its one delegated owner target.
Fresh child declarations cannot enter this eligibility set. Discovery does not
install definitions, infer new permissions or consume the original proof budget.

The fallback scan shares a 64-statement counter across both source arms and
uses the existing eight-selection bound. Different eligible write targets
reject; no-write candidates do not manufacture authority. Unsupported source
statements reject, and type/signature/seal/visibility checks remain the work of
the complete original owner/staging proof. Invalid terminal shapes do not bypass
the preferred scan by falling through to the new route.

The selected name passes the same ownership check as a terminal export. Only
then does its owner delegate the existing proof-only `Target` capability. First
RHS reads retain incoming captures; definite replacements advance source
versions. Conditional earlier writes still retain the actual current value on
skipped paths. Fresh children, constant seals and unrelated entering bindings
keep their existing isolation and write restrictions.

## Original Retention Work
