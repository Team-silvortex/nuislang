# Native Private Trailing Return Updates V1

Status: worktree follow-up after Git baseline `8a760089` (`beta-0.16.3`).
This extends the [retention-tail checkpoint](nuis-native-private-retention-return-updates-v1.md)
without changing common YIR, ABI, Nustar or backend effect authority. No version
bump, commit or push is implied.

## Target And Tail

Terminal discovery now considers only eligible existing owned unsealed bools.
A fresh final `let` or `const` is private source work, not a new export.
If neither terminal tree identifies an eligible export, the existing bounded
read-only scan finds earlier actual writes to the prefix-owned or delegated
target. Fresh child names and no-write candidates cannot manufacture authority.
Different eligible targets reject; full source proof still checks every statement.

The existing proof-only owner capability delegates just that target. The final
private binding is appended to the same staging environment as its prefix.
It cannot reset seals or prior definitions, grant another entering write, drop
unused calls/checks, leak a private name or replay an earlier RHS. Only the
actual current target is transported out, without invented source work.

Work-only child stages may retain the one already delegated owner target,
including conditions whose two outcomes retain and branches with private scalar
work. This is not root write evidence: an undelegated root still requires an
actual eligible source write. All original child conditions/work are fully proved
and charged; delegation neither installs a definition nor bypasses capture checks.

Final scalar `let` and admitted owned-bool logical-root `const` statements use
the existing staging rules. This is not generalized scalar-constant admission.
Original complete return trees and guards remain intact; actual false returns
still exit the callee and the caller continuation remains ordered. Malformed
candidates reject atomically before generated names or helpers are installed.

## Shared Limits

Each update arm retains its original at-most-16-statement prefix plus one
terminal statement. The trailing statement is original charged work, not an
extra budget. Empty/current-value transport creates no source node or expression.
The whole tree shares 64 nodes, 256 expressions, 32 logical edges, eight selection
levels, below-32 expression depth and 31 captures plus a gate.
The read-only discovery counter remains separately bounded to 64 source statements.

Tests cover old-read/replacement/conditional captures, both selected polarities,
final unused calls, fresh private rebindings and seals, complete returns and
atomic vetoes for extra entering targets, changed seals, hidden roots, wrong
types, late sibling leaks, loops and partial exits. Exact original accounting is
seven nodes / 14 expressions / two logical edges; each one-less budget rejects.
Adjacent prefix 16/17, nodes 64/65, edges 32/33, depth 8/9 and discovery 64/65
boundaries are independently tested.

## Remaining Boundary

Terminal private-child selections after an existing-target update still need a
separate export/retention proof: a terminal child write must stay private rather
than be forced into the ancestor target.
That later [terminal-private-child follow-up](nuis-native-private-terminal-child-return-updates-v1.md)
now proves one private child target; the 615-test receipt above remains this
earlier checkpoint's acceptance, not fresh evidence for the later extension.
Root no-write candidates must remain without authority. Hidden logical roots,
arbitrary entering writes, mixed/partial
exits, loops, resource transport and generalized effects remain separate.
This scalar-host acceptance does not establish new GPU/Linux/Windows execution,
measured speedups, authentication, formal memory safety or completed self-hosting.
Full workspace and strict Clippy acceptance remain separate.
