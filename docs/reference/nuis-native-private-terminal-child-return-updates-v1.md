## Private Child And Ancestor

A terminal selection may update one existing exact owned unsealed bool child
already defined in its private prefix and absent from the entering scope.
A separate read-only classifier shares a 64-source-statement counter across
the terminal arms and the existing eight-selection depth bound.
It uses the same eligible names as owner discovery. Different eligible source
write targets reject; classification grants no new permission or definition.

An actual private-child candidate reuses the existing child owner/staging proof.
The complete terminal selection runs at its original site and stays private.
Its original conditions, checks, calls, seals, child reads and branch retention
are all proved; the enclosing arm transports only the actual current ancestor.
Existing ancestor-target terminal selections retain their original proof route.

Fresh declarations cannot manufacture outward authority. An undelegated root
still needs actual source write evidence for its existing ancestor target.
A work-only descendant may retain its already delegated owner, without turning
that permission into a source definition. Entering names other than the exact
child target stay read-only inside the child proof. Dual ancestor/child writes
and multiple eligible child targets remain outside this selected extension.

## Original Work And Limits

Child transport adds no invented original source nodes or expressions.
Old reads before definite replacements remain captures; conditional ancestor
writes preserve the current incoming value on skipped paths. Private child and
grandchild names cannot become parent helper captures or late sibling reads.
All failure remains atomic before generated helper/name installation.

The whole tree shares 64 nodes, 256 expressions, 32 logical edges, eight selection
levels, below-32 expression depth and 31 captures plus a gate.
Each arm retains its at-most-16-statement prefix plus one terminal statement.
Read-only classification does not enlarge these original execution budgets.

Six NIR units cover paired/one-sided/nested private-child outcomes, seals and
unused work, old-read/replacement/conditional captures, exact original accounting
at nine nodes / 16 expressions / two logical edges, and one-less rejection.
Adjacent prefix 16/17, nodes 64/65, edges 32/33, depth 8/9, discovery 64/65
and capture 31/32 boundaries are independently checked. Negative/mutated-NIR
cases cover root no-write authority, entering/sealed/nonbool/dual-target writes,
hidden roots, partial exits, loops, malformed types and late sibling leaks.

## Remaining Boundary

Terminal mixed ancestor/private-child updates with one outward target require a
separate permission/version proof. Their child writes must stay private while
actual ancestor updates still publish; this cannot become arbitrary incoming or
multi-target write authority. Root no-write candidates, hidden logical leaves,
mixed/partial exits, loops, resources and generalized effects remain separate.
The later [terminal mixed-update follow-up](nuis-native-private-mixed-return-updates-v1.md)
records that distinct proof. The 623-test acceptance above remains historical,
not fresh evidence for the later extension.
This scalar-host acceptance does not establish new GPU/Linux/Windows execution,
measured speedups, authentication, formal memory safety or completed self-hosting.
Full workspace and strict Clippy acceptance remain separate.
